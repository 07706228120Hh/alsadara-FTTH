## الخطوة 3 — جدران الحماية (الأخطر — بالترتيب، s2 أولاً)

### قواعد السماح المقترحة لكل خادم (الباقي يُسقَط تلقائياً)
> ⚠️ **أكّد المنفذ العام الفعلي لكل خدمة**. الافتراض: الخدمات خلف Nginx على **443**. إن كان الباكند مكشوفاً مباشرةً على منفذ آخر (مثل 5000/8080) **أضِف قاعدته** وإلا ستسقط الخدمة.

| الخادم | قواعد accept |
|---|---|
| **كل الخوادم** | `SSH 22` ← `<<ADMIN_IP>>` (مصدر مخصّص) · `ICMP any` (اختياري للمراقبة) |
| s2.my `1266939` | + `HTTPS 443 ← any` |
| srv1587653 `1587653` | + `HTTPS 443 ← any` |
| alsadara.app `1303378` | + `HTTPS 443 ← any` · `HTTP 80 ← any` (Let's Encrypt) |
| WHATS.API `1225235` | + `HTTPS 443 ←` **IP الباكند فقط** `148.230.104.175` (لا any) |
| srv991906 `991906` | + `HTTPS 443 ← any` (webhooks n8n؛ للوحة الإدارة اعتمد مصادقة n8n) |
| s-main.my `1239550` | + `HTTPS 443 ← any` · `HTTP 80 ← any` · **Postgres 5432: لا قاعدة عامّة** (داخلي فقط) |

### تسلسل التنفيذ لكل خادم (عبر API هوستنكر — أنفّذه أنا بموافقتك خطوة بخطوة)
1. `vps_firewall_create` باسم (مثل `fw-s2`).
2. `vps_firewall_create-rule` لكل قاعدة (SSH من ADMIN_IP أولاً! ثم 443…).
3. `vps_firewall_activate` (firewallId, virtualMachineId).
4. **اختبر فوراً**: `ssh` يعمل؟ `https` يعمل؟ — إن لا: كونسول VNC + `vps_firewall` إلغاء التفعيل.
5. انتقل للخادم التالي. **s-main أخيراً** (الأحرج).

↩️ تراجع لأي خادم: إلغاء تفعيل جداره (يعود مفتوحاً) أو تصحيح قاعدة + إعادة مزامنة.

## ما أحتاجه منك لإكمال هذا (قبل النافذة)
1. **`<<ADMIN_IP>>`**: IP إدارتك الثابت (لقاعدة SSH). *(لو IP متغيّر: نفتح SSH من نطاق مزوّدك أو عبر VPN — ناقشه.)*
2. **المنفذ العام الفعلي** لكل خدمة (443 عبر Nginx؟ أم منفذ مباشر؟).
3. تأكيد: القاعدة على **s-main** والباكند عليه أيضاً؟ والساس/الواتساب أين بالضبط؟
4. بيانات SSH/Postgres (لخطوتي النسخ والتدوير) — تبقى عندك، تُدخَل وقت التنفيذ.

> فور تزويدي بـ ADMIN_IP + المنافذ، أُحوّل جدول القواعد إلى **استدعاءات API جاهزة لكل خادم**، فننفّذها منتصف الليل بسرعة وأمان (s2 أولاً).
