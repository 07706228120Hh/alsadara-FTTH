مرجع SAS4 API الكامل بالعربي

SASv4 هو نظام فوترة وخادم AAA (مصادقة، تخويل، محاسبة) لمزودي الإنترنت من شركة Snono Systems. هذه الصفحة تشرح كل endpoint موثّق في مجموعة Postman الرسمية (9 مجلدات، 66 طلب)، مع الـ payload المفكوك، عينات الاستجابة، وملاحظات عملية لربط منصة الصدارة (Ramzbot) كنقطة مركزية لكل شركات الإنترنت التي تعمل على SAS4.

نظرة عامة على النظام

SAS4 يعمل كـ RADIUS server مرتبط بأجهزة NAS (غالباً MikroTik) ويدير المستخدمين (المشتركين)، المدراء (Managers/Resellers)، الباقات (Profiles)، الكروت، الفواتير والتقارير. النظام مبني على Laravel (PHP) ولهذا ترى في الروابط index.php/api/ وصيغة Laravel Pagination في الاستجابات.

يوجد واجهتان منفصلتان للـ API، ولكل واحدة مسار وأساس مصادقة مختلف:

الواجهةالمسار الأساسيمن يستخدمهانموذج الصلاحيات
Admin API (لوحة الإدارة)http://{host}/admin/api/index.php/api/المدير/الموزع (Manager) — هذا ما تستخدمه المنصة للتفعيل والشحن وإدارة المشتركينACL Group لكل مدير، الصلاحيات تبدأ بـ prm_*
User Portal API (بوابة المشترك)http://{host}/user/api/index.php/api/المشترك النهائي — لتطبيق العميل (رصيدي، استهلاكي، تغيير باقتي)صلاحيات prm_ucp_*

الهيكل الهرمي: admin ← Managers (موزعون، لكل واحد رصيد و debt_limit ونقاط مكافآت) ← Users (المشتركون، لكل واحد profile وتاريخ انتهاء ورصيد). كل مدير يرى فقط المستخدمين التابعين له ولمدرائه الفرعيين.

مفاهيم ستتكرر: profile_id الباقة، parent_id المدير المالك للمشترك، transaction_id رقم UUID تولده أنت في كل عملية مالية لمنع التكرار، method طريقة الدفع (credit من رصيد المدير أو reward_points أو card بكرت).

المصادقة — JWT Bearer

كل الطلبات (عدا login/register) تحتاج هيدر Authorization: Bearer <token>. تحصل على التوكن من POST /admin/api/index.php/api/login بإرسال payload مشفّر يحوي اسم المدير وكلمة مروره واللغة. نوع المنحة المستخدم هو Client Credentials Grant.

بعد الحصول على التوكن، الطريقة القياسية في SAS4 لتحميل الواجهة هي: GET /api/auth لمعرفة بيانات المدير وصلاحياته (قائمة prm_*) وميزات الرخصة (features مثل sastrack وfreezone) وتاريخ انتهاء الرخصة، ثم GET /api/resources/menu لمعرفة القوائم المسموح بها، وGET /api/resources/language/{code} لملف الترجمة.

التوثيق لا يذكر مدة صلاحية التوكن. عملياً في المنصة: خزّن التوكن لكل شركة، وأعد تسجيل الدخول تلقائياً عند أي استجابة 401 أو عند status غير 200 مع رسالة انتهاء الجلسة.

تشفير الطلبات — AES (CryptoJS)

كل طلب POST يجب أن يُرسل بجسم واحد فقط اسمه payload (كـ application/x-www-form-urlencoded أو JSON) وقيمته هي JSON الفعلي مشفّراً بـ CryptoJS.AES.encrypt(JSON.stringify(data), KEY). المفتاح الظاهر في التوثيق الرسمي هو:

abcdefghijuklmno0123456789012345

نقطة تقنية مهمة جداً لأي تنفيذ خارج JavaScript: عندما تمرّر لـ CryptoJS مفتاحاً كنص (passphrase) لا كبايتات، فهو يستخدم صيغة OpenSSL: يولّد salt عشوائي 8 بايت، يشتق المفتاح (32 بايت) والـ IV (16 بايت) بـ EVP_BytesToKey (MD5 متكرر)، ويشفّر بـ AES-256-CBC مع PKCS7، ثم يخرج Base64 لـ "Salted__" + salt + ciphertext. لهذا كل الـ payloads في التوثيق تبدأ بـ U2FsdGVkX1 (وهي "Salted__" بعد Base64). أكواد Dart وPHP وPython الجاهزة في قسم أكواد التشفير.

مثال التوثيق (Node.js)
const request = require('request');
const CryptoJS = require("crypto-js");
const form = {user: 'admin', password: 'snonosystems'};
const cypData = CryptoJS.AES.encrypt(JSON.stringify(form),
  'abcdefghijuklmno0123456789012345');
request.post({
  url: 'http://demo4.sasradius.com/admin/api/index.php/api/login',
  json: true,
  body: { payload: cypData.toString() }
}, (err, res, body) => console.log(res.statusCode, body));

أكواد التشفير الجاهزة (متوافقة مع CryptoJS)

كل الأكواد التالية تنتج نفس صيغة OpenSSL التي يفهمها SAS4. الدالة encrypt ترسل، وdecrypt مفيدة لفك أمثلة التوثيق أو أي استجابة مشفّرة.

Dart / Flutter (يحتاج حزمتي encrypt وcrypto)
import 'dart:convert';
import 'dart:math';
import 'dart:typed_data';
import 'package:crypto/crypto.dart';
import 'package:encrypt/encrypt.dart' as enc;

class Sas4Crypto {
  static const magic = 'Salted__';

  // EVP_BytesToKey (MD5) كما في OpenSSL/CryptoJS
  static List<Uint8List> _kdf(List<int> pass, List<int> salt) {
    var out = <int>[]; var prev = <int>[];
    while (out.length < 48) {
      prev = md5.convert([...prev, ...pass, ...salt]).bytes;
      out.addAll(prev);
    }
    return [Uint8List.fromList(out.sublist(0, 32)),
            Uint8List.fromList(out.sublist(32, 48))];
  }

  static String encrypt(Map data, String passphrase) {
    final salt = Uint8List.fromList(
        List.generate(8, (_) => Random.secure().nextInt(256)));
    final kv = _kdf(utf8.encode(passphrase), salt);
    final e = enc.Encrypter(enc.AES(enc.Key(kv[0]), mode: enc.AESMode.cbc));
    final ct = e.encryptBytes(utf8.encode(jsonEncode(data)), iv: enc.IV(kv[1]));
    return base64.encode([...utf8.encode(magic), ...salt, ...ct.bytes]);
  }

  static String decrypt(String b64, String passphrase) {
    final raw = base64.decode(b64);
    final salt = raw.sublist(8, 16); final ct = raw.sublist(16);
    final kv = _kdf(utf8.encode(passphrase), salt);
    final e = enc.Encrypter(enc.AES(enc.Key(kv[0]), mode: enc.AESMode.cbc));
    return e.decrypt(enc.Encrypted(Uint8List.fromList(ct)), iv: enc.IV(kv[1]));
  }
}
// الإرسال:  body: {'payload': Sas4Crypto.encrypt({...}, key)}
PHP (للـ backend / n8n Code node بـ Python أدناه)
function sas4_encrypt(array $data, string $pass): string {
  $salt = random_bytes(8);
  $d = ''; $prev = '';
  while (strlen($d) < 48) { $prev = md5($prev.$pass.$salt, true); $d .= $prev; }
  $key = substr($d, 0, 32); $iv = substr($d, 32, 16);
  $ct = openssl_encrypt(json_encode($data), 'aes-256-cbc', $key, OPENSSL_RAW_DATA, $iv);
  return base64_encode('Salted__'.$salt.$ct);
}
function sas4_decrypt(string $b64, string $pass): string {
  $raw = base64_decode($b64); $salt = substr($raw, 8, 8); $ct = substr($raw, 16);
  $d = ''; $prev = '';
  while (strlen($d) < 48) { $prev = md5($prev.$pass.$salt, true); $d .= $prev; }
  return openssl_decrypt($ct, 'aes-256-cbc', substr($d,0,32), OPENSSL_RAW_DATA, substr($d,32,16));
}
Python (FastAPI / n8n) — pip install pycryptodome
import json, os, base64, hashlib
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad

def _kdf(p: bytes, salt: bytes):
    d = b''; prev = b''
    while len(d) < 48:
        prev = hashlib.md5(prev + p + salt).digest(); d += prev
    return d[:32], d[32:48]

def sas4_encrypt(data: dict, passphrase: str) -> str:
    salt = os.urandom(8); key, iv = _kdf(passphrase.encode(), salt)
    ct = AES.new(key, AES.MODE_CBC, iv).encrypt(pad(json.dumps(data).encode(), 16))
    return base64.b64encode(b'Salted__' + salt + ct).decode()

def sas4_decrypt(b64: str, passphrase: str) -> str:
    raw = base64.b64decode(b64); key, iv = _kdf(passphrase.encode(), raw[8:16])
    return unpad(AES.new(key, AES.MODE_CBC, iv).decrypt(raw[16:]), 16).decode()

خطة الربط المركزي في منصة الصدارة

الهدف: أن تكون المنصة الطبقة المركزية الوحيدة التي يتعامل معها الوكلاء والمشتركون، بينما كل شركة إنترنت تحتفظ بسيرفر SAS4 الخاص بها. المنصة لا تلمس قاعدة بيانات SAS4 مباشرة، بل تتحدث معه عبر Admin API بحساب مدير (Manager) مخصص لكل شركة.

ملاحظات أمنية ونقاط انتبه لها (مُستنتجة من التوثيق نفسه)

  • تسريب أسرار الـ NAS في قائمة المتصلين: استجابة POST /index/online ترجع كائن nas_details كاملاً بما فيه secret (RADIUS secret) وapi_username/api_password (MikroTik API) وsnmp_community. لا تمرّر هذه الاستجابة كما هي لتطبيق الوكلاء — صفّها في الـ Gateway.
  • كلمة المرور بنص واضح: GET /user/overview/{id} يرجع حقل password للمشترك. مفيد للوكيل لكن يجب حصره بصلاحية.
  • التشفير ليس أماناً حقيقياً: مفتاح AES ثابت ومنشور في التوثيق؛ اعتبره "تغليفاً" فقط. الأمان الفعلي من HTTPS بين المنصة وسيرفرات الشركات (التوثيق يستخدم http — اطلب من كل شركة تفعيل TLS أو مرّر عبر VPN/WireGuard).
  • Idempotency: كل عملية مالية تحمل transaction_id (UUID). بوابة المشترك تستخدم uuid بنفس الغرض في /user/activate. ولّده مرة واحدة لكل نقرة وأعد استخدامه عند إعادة المحاولة.
  • حقول بأخطاء إملائية في التوثيق: diraction بدل direction، وuser في شرح login بينما المثال الفعلي يستخدم username. الأمثلة الفعلية هي المرجع الأصح.
  • تغيير كلمة مرور المشترك من بوابته موثّق بأنه "bugged" وبانتظار إصلاح — اختبره على كل إصدار قبل الاعتماد عليه.
  • الرخصة: GET /auth يرجع license_expiration؛ راقبها لكل شركة ونبّه قبل انتهائها لأن التفعيلات ستتوقف.
  • مجلد Dashboard فارغ في التوثيق الرسمي — لا يوجد endpoint موثّق للوحة الإحصائيات؛ ابنِ إحصائيات المنصة من قوائم المستخدمين والمتصلين.
