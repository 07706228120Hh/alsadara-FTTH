# القيود غير المتوازنة في مسار FTTH — السبب الجذري والإصلاح — 2026-11-22

> تحقيق + تطوير + اختبار في بيئة معزولة. **لم يُنشَر، ولم تُعدَّل أي بيانات إنتاج، ولم تُمَسّ القيود الـ28 ولا الـ26 السابقة. «مزامنة» لم تُعدَّل بعد الختم.**

## 1) السبب الجذري
الدالة `FtthAccountingController.UpdateJournalEntryAmounts` (مسار **تعديل** مبالغ قيد عملية موجودة، تُستدعى من `FixBasePrices` ومن مسار تعديل آخر) تُحدّث **السطور القائمة فقط** في القيد. السيناريو المعطوب:
1. عملية تُفعَّل بسعر كامل (بلا خصم) ⇒ قيد متوازن يُنشأ **بلا سطر «مصاريف عروض 5110»** (لأن الخصم=0).
2. تُعدَّل العملية لاحقاً لتطبيق **خصم يدوي كامل** (ManualDiscount = كامل السعر).
3. عند إعادة حساب المبالغ: طرف التحصيل (مدين) = `totalCollected = المستقطع + الإيراد − الخصم = 0`، ورصيد الصفحة (دائن) = المستقطع (مثلاً 35,000). لكن **لا سطر 5110 قائم ليستوعب الخصم (35,000) على الجانب المدين** ⇒ القيد: مدين 0 / دائن 35,000 — **غير متوازن**.
4. لا حارس توازن على هذا المسار (كتابة مباشرة + تحديث رأس القيد) ⇒ يُحفَظ غير متوازن.

**مسار الإنشاء (`RecordActivation`) سليم** (فحص توازن ذاتي + المحرّك المركزي المحروس) — لذا **0 من الـ28** منه.

- التوزيع حسب نوع التحصيل: فنّي 18 (−145,000) · نقد 7 (−172,000) · وكيل 2 (−12,000) · آجل 1 (−35,000).
- مثالان مُشخّصان: `JE-2026-50822` (نقد، 50228، ManualDiscount=35,000=كامل) و`JE-2026-51129` (آجل، 50511، ManualDiscount=35,000). كلاهما: سطر تحصيل بمدين 0 + سطر رصيد الصفحة بدائن 35,000، بلا سطر 5110.
