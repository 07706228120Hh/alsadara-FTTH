# دليل نافذة الصيانة — تنفيذ بعد منتصف الليل

> نافذة صيانة مُحكمة الوقت لتنفيذ: **(أ) نشر نظام الساس المحاسبي** + **(ب) التأمين الفوري (نسخ احتياطي · تدوير أسرار · جدران حماية)**.
> مبدأ ذهبي: **نسخة احتياطية أولاً · خطوة-خطوة مع تحقّق · تراجع جاهز لكل خطوة · SSH يبقى مفتوحاً**.
> الرموز `<<...>>` = قيم تملؤها أنت (انظر §8).

---

## 0) التحضير قبل منتصف الليل (T-minus) — لا يمسّ الإنتاج

**أجهّزه أنا الآن في المستودع (بموافقتك):**
- [ ] بناء إصدار الإنتاج: إعادة `isProduction=true` في `api_config.dart:14` و`sadara_api_service.dart:24` (فرع إصدار منفصل أو قبيل البناء).
- [ ] سكربتات جاهزة: `deploy/backup.sh` · `deploy/deploy-backend.sh` · قواعد الجدار (payload API).
- [ ] دمج فرع `feature/sas-agent-integration` → `main` بعد مراجعة، أو وسمه للإصدار.
- [ ] بناء `flutter build windows --release` (المُثبّت/التحديث) جاهزاً.

**تجمعه أنت قبل النافذة:**
- [ ] وصول SSH لكل خادم + صلاحيات sudo.
- [ ] بيانات اتصال Postgres الإنتاج (host/port/db/user/pass).
- [ ] طريقة تشغيل الباكند الحالي (systemd? docker? pm2?) واسم الخدمة.
- [ ] IP إدارتك الثابت (لقاعدة SSH في الجدار).
- [ ] وصول n8n (لتحديث مفتاح API).
- [ ] تأكيد أيّ خادم يستضيف ماذا (DB/الباكند/الساس/الواتساب).

## 1) النسخ الاحتياطي (شبكة الأمان — أول خطوة إلزامية) · ~10د

```bash
# على خادم القاعدة
TS=$(date +%Y%m%d_%H%M%S)
mkdir -p ~/backup_$TS
# قاعدة البيانات كاملة
PGPASSWORD='<<PGPASS>>' pg_dump -h <<PGHOST>> -p <<PGPORT>> -U <<PGUSER>> -Fc <<PGDB>> > ~/backup_$TS/db.dump
# ملفات الإعداد الحسّاسة + مفاتيح DataProtection + SQLite الساس
cp -r <<APP_DIR>>/.env <<DP_KEYS_PATH>> <<SAS_SERVICE_DIR>>/data/sas.db ~/backup_$TS/ 2>/dev/null
ls -lh ~/backup_$TS   # تأكّد أنّ db.dump غير فارغ
```
✅ تحقّق: حجم `db.dump` منطقي. **لا تكمل بلا نسخة سليمة.**
↩️ تراجع: `pg_restore -c -d <<PGDB>> ~/backup_$TS/db.dump`.

## 2) تدوير الأسرار · ~15د

```bash
# ولّد مفاتيح جديدة قوية
NEW_API_KEY=$(openssl rand -hex 24)        # بديل sadara-internal-2024-secure-key
NEW_SAS_SECRET=$(openssl rand -hex 24)      # بديل سرّ خدمة الساس
echo "API=$NEW_API_KEY" ; echo "SAS=$NEW_SAS_SECRET"   # احفظهما بأمان
```
1. **الباكند** (env الخدمة): `SADARA_INTERNAL_API_KEY=$NEW_API_KEY` · `SADARA_SAS_INTERNAL_SECRET=$NEW_SAS_SECRET`.
2. **خدمة الساس (sidecar)**: نفس `SADARA_SAS_INTERNAL_SECRET`.
3. **n8n**: حدّث عقدة الـAPI بالمفتاح الجديد.
4. **التطبيق**: ابنِ الإصدار بالمفتاح الجديد (env وقت البناء / AppSecrets) — وزّع المُثبّت/التحديث.
5. أعِد تشغيل الباكند + الساس بعد ضبط env.

✅ تحقّق: `curl -H "X-Api-Key: $NEW_API_KEY" https://api.<domain>/api/.../internal-endpoint` ← 200.
↩️ تراجع: أعِد المفتاح القديم في env + أعِد التشغيل (حتى تُحدَّث الأطراف).
⚠️ المفتاح القديم مكشوف في تاريخ Git — بعد الاستقرار: `git filter-repo` لإزالته (خارج النافذة).

## 3) نشر نظام الساس المحاسبي · ~30د

> كل ما بُني: وحدة الساس + الفوترة/المحاسبة/الذمم/التسعير/حقول المواطن + تبويب الحسابات. مرجع: `PRE_DEPLOY_CHECKLIST.md`.

**3.1 الكود:** ادمج الفرع → `main`. **احذف** `src/Backend/API/Sadara.API/Controllers/SasDevController.cs` (متحكّم المحاكاة). تأكّد `isProduction=true` (الملفّان).

**3.2 الهجرات** (إضافية بحتة — بعد النسخة الاحتياطية):
```bash
# من مجلد الباكند على الخادم (أو dotnet ef عن بُعد)
dotnet ef database update --project src/Backend/Core/Sadara.Infrastructure --startup-project src/Backend/API/Sadara.API
# الهجرات الأربع للساس: AddSasAgentModule · AddSasSourceToSubscriptionLog · AddSasPricingAndProfile · AddSasCitizenPayment
```
✅ تحقّق: `\dt "Sas*"` تُظهر: SasAccounts · SasPackagePrices · SasSubscriberProfiles · SasCitizenPayments + أعمدة Source على SubscriptionLogs.

**3.3 خدمة الساس (sidecar):**
```bash
cd <<SAS_SERVICE_DIR>>
python -m venv .venv && .venv/bin/pip install -r requirements.txt
# systemd unit على 127.0.0.1:8100 مع SADARA_SAS_INTERNAL_SECRET (غير مكشوف للإنترنت)
sudo systemctl enable --now sas-sidecar && curl -s 127.0.0.1:8100/health   # {"status":"ok"}
```

**3.4 الباكند .NET:** `dotnet publish -c Release` → نقل للخادم → ضبط env (الاتصال + المفاتيح + `DataProtection:KeysPath` ثابت + `SasService:BaseUrl=http://127.0.0.1:8100`) → `systemctl restart <<BACKEND_SVC>>`.

**3.5 التطبيق:** وزّع إصدار ويندوز الجديد (المُثبّت/التحديث التلقائي).

✅ تحقّق: دخول موظّف → تبويب الساس يعمل · الحسابات تُحمّل · تفعيل تجريبي (مشترك اختباري) → قيد يظهر في «نظام الساس».
↩️ تراجع: استعادة النسخة + إرجاع الإصدار السابق للباكند/التطبيق (الهجرات إضافية فلا تكسر الإصدار القديم).

## 4) جدران الحماية · ~25د (الأخطر — بعناية)

> ⚠️ جدار هوستنكر **يُسقط كل الوارد افتراضياً**. أي خطأ في قاعدة SSH = **قفل كامل**. كونسول hPanel (VNC) = خطّة الإنقاذ.

**الترتيب الآمن:** ابدأ بـ`s2.my` (الأقل حرجاً) → تأكّد من بقاء وصولك → عمّم.

**القواعد لكل خادم (accept؛ الباقي يُسقَط تلقائياً):**
- كل الخوادم: `SSH 22 ← <<ADMIN_IP>>` (مصدر مخصّص) + `ICMP` (اختياري).
- `s-main`: `HTTPS 443 ← any` · `HTTP 80 ← any` · **Postgres 5432: لا قاعدة عامّة** (داخلي/شبكة خاصّة فقط).
- `alsadara.app`: `443/80 ← any` · منفذ الساس داخلي فقط.
- `WHATS.API`: `443 ← any` (إن لزم) · منفذ الواتساب ← IP الباكند فقط.
- `srv991906` (n8n): `443 ← any` أو `<<ADMIN_IP>>`.
- `srv1587653`: `443` + `SSH`.

**التنفيذ (عبر API هوستنكر — أنا أنفّذه بموافقتك خطوة بخطوة):**
1. `firewall_create` باسم لكل نمط.
2. `replace-all-rules` بالمجموعة الكاملة دفعةً + `sync=true`.
3. `firewall_activate` للخادم → **اختبر فوراً**: SSH + HTTPS يعملان؟ إن لا → كونسول VNC وأزِل الجدار.
4. كرّر لبقية الخوادم.

✅ تحقّق لكل خادم: SSH يعمل + الخدمة العامّة (443) تعمل + المنافذ الداخلية مغلقة للخارج (`nmap`/`curl` من خارج).
↩️ تراجع: إلغاء تفعيل الجدار للخادم (يعود مفتوحاً) أو تصحيح القاعدة + sync.

## 6) خطط التراجع (ملخّص)
| المرحلة | التراجع |
|---|---|
| الأسرار | إرجاع المفتاح القديم في env + إعادة تشغيل |
| الهجرات | إضافية — لا تكسر القديم؛ عند الضرورة `pg_restore` النسخة |
| الباكند/التطبيق | إرجاع الإصدار السابق (artifact محفوظ) |
| الجدار | إلغاء تفعيله للخادم أو تصحيح القاعدة + sync |
| كارثي | `pg_restore` النسخة الكاملة + إصدار سابق |

## 8) ما أحتاجه منك (لإكمال الدليل بدقّة قبل النافذة)
1. **IP إدارتك الثابت** (`<<ADMIN_IP>>`) — لقاعدة SSH.
2. **بيانات Postgres الإنتاج** (host/port/db/user/pass) ومكانه (أي خادم).
3. **طريقة تشغيل الباكند** (systemd/docker/pm2) + اسم الخدمة (`<<BACKEND_SVC>>`) + مجلّده (`<<APP_DIR>>`).
4. **مجلّد خدمة الساس** على الخادم (`<<SAS_SERVICE_DIR>>`) + مسار مفاتيح DataProtection (`<<DP_KEYS_PATH>>`).
5. **المجال** (`api.<domain>`) وأي خادم يخدمه.
6. تأكيد: **نشر الساس + التأمين معاً** في النافذة، أم التأمين فقط؟

> ما إن تزوّدني بهذه، أملأ كل `<<...>>`، أجهّز السكربتات والجدران كـpayload جاهز، وأدمج/أبني للإصدار — فنبدأ منتصف الليل بتنفيذ سريع متسلسل.
