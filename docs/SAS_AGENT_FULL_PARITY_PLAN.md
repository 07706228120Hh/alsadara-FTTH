## 1) القرار المعماري الجوهري (يحدّد كل ما بعده)

| البُعد | الصدارة الحالية | تطبيق الوكلاء | القرار للتطابق |
|---|---|---|---|
| حالة المشتركين | **بلا حالة** (بروكسي يمرّر خاماً) | **مزامنة محلية** (جدول `Subscriber` + `sas_account_id`) | نحتاج مزامنة محلية لتمكين الفلترة/البحث/عدّ الانتهاء/التذاكر/ربط OTP |
| منطق الساس | خدمة Python نحيلة (8 نقاط قراءة) | باكند FastAPI كامل (بروكسي + عمليات + تذاكر + بوابة + بلنك + كشف دمج) | **ترقية الـ sidecar ليكون باكند الوكلاء الكامل** |
| الواجهة | 7 تبويبات (بعضها هيكلي) | ~24 شاشة/ميزة | **نقل كل الشاشات** |

**المعمارية المستهدفة:** بدل خدمة Python النحيلة، نُشغّل **باكند الوكلاء الكامل** (المنسوخ أصلاً في `modules/sas-agent/backend`) كخدمة داخلية (sidecar) بقاعدته الخاصة (SQLite محلي / مخطّط Postgres)، وتظل **بوّابة .NET** هي الهوية والعزل (تمرّر المستخدم المُصادَق + حساب الساس الخاص به). و**وحدة Flutter** `lib/sas_agent` تنقل كل شاشات الوكلاء بثيم الصدارة.

```
Flutter (lib/sas_agent — كل الشاشات) → JWT → بوّابة .NET (/api/sas-agent/*)
   → [127.0.0.1 + سرّ داخلي + سياق المستخدم/الحساب] → باكند الوكلاء الكامل (Python + قاعدته)
      → عملاء SAS4 (sas_client/sas_user_client) → خوادم الساس
      → واتساب (whatsapp-server) · العقارات (premises)
```

## 4) المراحل التنفيذية

### المرحلة أ — الباكند الكامل (الأساس)
- **أ.1** ترقية الـ sidecar: تشغيل `modules/sas-agent/backend` (باكند الوكلاء الكامل) كخدمة داخلية بقاعدته الخاصة، بدل الخدمة النحيلة. تفويض المصادقة من .NET (المستخدم + حساب الساس يُمرّران من البوّابة).
- **أ.2** المزامنة المحلية: تفعيل `sas_sync` (جدول Subscriber/Agent/AgentReport/MergeFinding محلياً) — يمكّن الفلترة/البحث/الانتهاء/التذاكر/كشف الدمج.
- **أ.3** توسيع بوّابة .NET `SasAgentController` بكل نقاط الوكيل (تمرير للـ sidecar مع العزل الثلاثي + `_redact`): عمليات المشترك المفردة/الجماعية، إنشاء/تعديل/حذف، الاسترداد، التفاصيل والتبويبات، المتصلون، الوكلاء وإجراءاتهم، السجلات، التقارير، الترخيص، المقاطعة/البلنك، بوابة المشترك، التذاكر.
- **الجهد:** كبير.

### المرحلة ب — الواجهة الكاملة (نقل الشاشات)
نقل كل شاشات الوكلاء إلى `lib/sas_agent` بثيم الصدارة (Cairo/app_theme/متجاوب سطح المكتب):
- تفاصيل المشترك + شريط الإجراءات + التبويبات الثمانية · نماذج المشترك/الوكيل · تبويبات اللوحة (online/managers/logs/finance-KPI/health) · التقارير + المجمّعة + الترخيص · مستكشف SAS (WebView) · إدارة الوكلاء + المقاطعة · إثراء الداشبورد + نموذج التصريح · مزامنة/اختبار الحسابات · التذاكر · بوابة المشترك.
- **الجهد:** كبير جداً (~24 شاشة).

### المرحلة ج — الواتساب (من `C:\AluklaaApp`)
- نقل `whatsapp-server` (خادم Node/JS مستقل) + تكامله (OTP + أي إرسال جماعي) وربطه بخدمة الساس. جرد تفصيلي عند الوصول لهذه المرحلة.
- **الجهد:** متوسط–كبير (يعتمد على حجم وحدة الواتساب في AluklaaApp).

### المرحلة د — العقارات/العنونة الوطنية (من `C:\AluklaaApp/backend/app/premises`)

- **الجهد:** متوسط–كبير.

### المرحلة هـ — الاختبارات والتشديد

- **الجهد:** متوسط.

## 5) المخاطر والقرارات

| الخطر/القرار | التفصيل |
|---|---|
| **العمليات الكتابية على ساس حقيقي** | التفعيل/التمديد/الإيداع/السحب تغيّر بيانات فعلية على خادم الساس — تحتاج تأكيدات + idempotency (موجود في Aluklaa: transaction_id/uuid) + اختبار على حساب تجريبي |
| **المزامنة المحلية = حالة جديدة** | إضافة جداول مشتركين محلياً للـ sidecar — قرار تخزين (SQLite للـ sidecar أم مخطّط Postgres) + سياسة احتفاظ |
| **حجب الأسرار** | يجب نسخ `_redact` قبل تمرير أي استجابة ساس خام للواجهة |
| **الواتساب** | خادم مستقل (whatsapp-server) — يحتاج تشغيلاً/نشراً منفصلاً + جلسة واتساب |
| **حجم العمل** | هذا **نقل منتج كامل** — يُنفّذ على مراحل متتابعة، كل مرحلة قابلة للاختبار وحدها |
| **العزل الثلاثي للصدارة** | يبقى مفروضاً في .NET لكل نقطة جديدة (company+owner+permission، fail-closed) — لا تُضعِفه |
