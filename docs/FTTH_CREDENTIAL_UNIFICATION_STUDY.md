## 4) الحالة المستهدفة — مصدر واحد (`FtthAccount`)

```
كل اعتماد FTTH = FtthAccount (مشفّر، لكل موظف، يدعم التعدّد)
        │
        ├── الدخول الصامت → login عبر FtthAccount فقط
        ├── المزامنة → تطابق operator.username ضد FtthAccount.Username → OwnerUserId
        ├── المحاسبة → القيد يُنسب لـ OwnerUserId (الموظف) كما الآن
        └── الإدارة → تبويب «الحسابات المرتبطة» فقط (إضافة/تعديل/حذف/تحقّق/أساسي/كشف)
```

**مبدأ العزل محفوظ:** كل حسابات FtthAccount معزولة بالشركة (CompanyId) + المالك (OwnerUserId)، والسرّ لا يُعاد في أي استجابة (كشف محروس بأدمن+تدقيق+rate-limit).

## 5) إعادة تصميم منطق المطابقة (الأهم)

**اليوم:** عملية FTTH فيها اسم منشئ (operator username) → يُطابَق ضد `User.FtthUsername/Username/FullName` → UserId.

**المستهدف:** عملية FTTH فيها اسم منشئ → يُطابَق ضد **`FtthAccount.Username`** (ضمن نفس الشركة) → **`FtthAccount.OwnerUserId`** = الموظف المالك → القيد يُنسب له.

**مزايا:**
- يدعم **تعدّد الحسابات** لكل موظف (موظف يملك عدّة حسابات FTTH/مشغّلين) — كل عملية تُنسب للمالك الصحيح عبر اسم الحساب لا اسم الموظف.
- مفتاح مطابقة **دقيق** (username الحساب) بدل `FullName` الهشّ.
- fallback `"sync"` يبقى للعمليات بلا حساب مطابق (أو تُعلَّم «غير منسوبة» للمراجعة).

**تغيير لازم في الباكند:** بناء خريطة المطابقة من `FtthAccounts` بدل `Users`:
```
map: FtthAccount.Username(lower) → { OwnerUserId, CompanyId, FullName(from owner) }
```
مع فهرس على `(CompanyId, Username)` للأداء.

## 6) نموذج البيانات والترحيل

| الخطوة | التفصيل |
|-------|---------|
| 1. **تطبيق هجرة `FtthAccount`** | جدول `FtthAccounts` + فهرس فريد مُرشّح `(CompanyId, OwnerUserId, Username)` — **مطبّق على الإنتاج مسبقاً** (v2.4.9). |
| 2. **Backfill من A إلى B** | `POST /api/linked-accounts/backfill-from-legacy` لكل شركة: ينشئ `FtthAccount` من `User.FtthUsername/Password` القديم (يشفّر القيمة). **لكن** قد تكون كلمات المرور القديمة مُصفّرة (المشكلة #1) ⇒ تحقّق أولاً. |
| 3. **إصلاح #1 قبل أي ربط جديد** | حتى لا تضيع كلمات مرور إضافية أثناء الانتقال. |
| 4. **تحقّق التغطية** | تقرير: كم موظفاً لديه A بلا B، وكم كلمة مرور مفقودة (تحتاج إعادة إدخال من الأدمن). |
| 5. **تحويل القراءات إلى B** | المزامنة + الدخول + العرض. |
| 6. **تجميد الكتابة في A** | إزالة endpoints الكتابة القديمة (`link-ftth-account`, حقل HR). |

## 7) مصير «ربط المشغلين» (الصفحة)

«ربط المشغلين» تؤدي وظيفتين: (أ) **جلب قائمة مشغّلي FTTH** من `admin.ftth.iq/api/teams/members` (نظرة شاملة: 37 مشغّل، مربوط/غير مربوط)، (ب) **الربط** بكتابة `User.FtthUsername`.

| الخيار | الوصف | التوصية |
|--------|------|---------|
| **أ) إلغاء كامل** | يُحذف التبويب؛ الربط حصراً عبر «الحسابات المرتبطة» لكل موظف يدوياً | يفقد النظرة الشاملة والربط الجماعي لـ37 مشغّلاً |
| **ب) إعادة توجيه (موصى)** | تبقى الصفحة كـ**نظرة شاملة** (تجلب المشغّلين من FTTH + تعرض حالة الربط من `FtthAccount`)، لكن زر «ربط» **ينشئ `FtthAccount`** بدل كتابة A | يحافظ على سهولة الربط الجماعي + مصدر واحد |

> **الأفضل: الخيار (ب)** — تبقى شاشة النظرة الشاملة مفيدة، لكن مصدر التخزين الوحيد يصبح `FtthAccount`. إن أصرّ المالك على الإزالة الكاملة، فالخيار (أ) ممكن لكن بجهد ربط يدوي أكبر.

## 8) قرار `CompanyFtthSettings` (اعتماد مزامنة المشتركين)

مزامنة **المشتركين** (قوائم العملاء) تستخدم اعتماداً **واحداً لكل شركة** (`CompanyFtthSettings`)، لا per-operator. الخيارات:

| الخيار | الوصف | ملاحظة |
|--------|------|-------|
| إبقاؤه منفصلاً | يبقى اعتماد شركة مخصّص للمزامنة | **لكن يجب تشفيره** (خام حالياً) |
| حساب FtthAccount «للشركة» | تعيين `FtthAccount` مملوك لمستخدم نظام/أدمن كـ«حساب المزامنة» | يربط المزامنة بحساب شخص (خطر إن غادر) |

> **التوصية:** إبقاء `CompanyFtthSettings` منفصلاً (غرضه مختلف) لكن **تشفيره** عبر `ISecretProtector`. توحيده مع FtthAccount ليس ضرورياً وقد يُدخل هشاشة.

## 14) الحل الشامل: ثلاثة مفاتيح مطابقة + «بطاقة هوية» كاملة لكل حساب

نُضيف إلى كيان `FtthAccount` الحقول:
- **`FtthMemberId`** (رقم عضو الفريق على FTTH، مثل `1838865`).
- **`DisplayName`** (اسم العضو) — موجود جزئياً كـ `Label`/`Role`.

تُجلب هذه من FTTH `/api/teams/members` (التي تربط **id ↔ username ↔ name ↔ role**) عند الربط، وتُحفظ مع الموظف المالك.

**المطابقة في المزامنة (بالأولوية):**
1. `createdBy` = **`FtthMemberId`** (رقمي) → المالك.
2. `createdBy` = **`Username`** → المالك.
3. `createdBy` = **`DisplayName`/الاسم** → المالك.
4. وإلا → غير منسوب (لا نخترع نسبة) + صمام أمان المكرّرات.

فسواء سجّل FTTH العملية بالرقم أو الاسم، تؤدّي لنفس الموظف.

## 15) التوحيد الكامل في «الحسابات المرتبطة» (قرار المالك 2026-10-23)

«الحسابات المرتبطة» = المكان الوحيد لإدارة اعتماد FTTH/SAS لكل موظف، ويضاف إليه زر **«ربط عضو FTTH»** (يجلب `/api/teams/members` ويحفظ الرقم+الاسم+اسم المستخدم+كلمة المرور مشفّرة).

**يُحذف/يُدمج:**
- **تبويب «ربط المشغلين»** (`ftth_operator_linking_page.dart`): يُدمج كزر «ربط عضو» داخل التبويب، أو يبقى نظرة شاملة للقراءة فقط من `FtthAccount` — لا تخزين منفصل.
- **بطاقة الحساب أسفل تبويب «معلومات الموظف»** (حقل FTTH القديم في `hr_info_tab.dart`): **تُزال**.
- الأعمدة القديمة `User.FtthUsername/FtthPasswordEncrypted` + endpoints `link-ftth-account`/`operators-linking`/`ftth-credentials`: تُلغى (آخر مرحلة).

**قرارات المالك المثبّتة:** `CompanyFtthSettings` يبقى منفصلاً (استيراد المشتركين) + يُشفَّر لاحقاً · تكرار اسم المستخدم لعدّة موظفين: المالك يُفرده لاحقاً (صمام الأمان يتخطّاه حتى حينها).
