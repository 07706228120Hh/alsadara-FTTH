# Testing Workflow — سير عمل الاختبارات

الهدف: رفع تغطية الاختبارات بكتابة اختبارات ناقصة وتشغيلها وتحليل الإخفاقات.

## السلسلة
```
Testing Task
  → testing-qa-agent
  → Inspect Existing Tests (فحص الاختبارات الحالية)
  → Identify Missing Tests (تحديد الناقص)
  → Write Tests (كتابة الاختبارات)
  → Run Tests (تشغيل الاختبارات)
  → Analyze Failures (تحليل الإخفاقات)
  → Report
```

## الخطوات بالتفصيل
1. **testing-qa-agent**: يستلم مهمة الاختبار ويحدد النطاق (Backend .NET / Flutter). المخرجات: task-template.
2. **Inspect Existing Tests**: فحص الاختبارات الموجودة لتجنّب التكرار وفهم الأنماط (مع ملاحظة أن الاختبارات الحالية ضعيفة). المخرجات: جرد للتغطية.
3. **Identify Missing Tests**: تحديد المسارات الحرجة غير المغطّاة (المصادقة، الصلاحيات، المحاسبة، API). المخرجات: قائمة ثغرات تغطية.
4. **Write Tests**: كتابة اختبارات واضحة وقابلة للتكرار دون تعديل كود الإنتاج إلا عند الضرورة وبالتنسيق مع الوكيل المختص. المخرجات: اختبارات جديدة.
5. **Run Tests**: تشغيل حزمة الاختبارات. المخرجات: نتائج التشغيل.
6. **Analyze Failures**: تحليل أي إخفاق وتحديد إن كان خطأ اختبار أم خطأ منتج. أخطاء المنتج → bugfix-workflow. المخرجات: تحليل.
7. **code-reviewer-agent** (إن لزم): مراجعة جودة الاختبارات.
8. **knowledge-manager-agent**: تحديث الذاكرة بحالة التغطية.

## بوابات الموافقة البشرية
- موافقة بشرية قبل أي تشغيل اختبارات تمس بيانات/خدمات الإنتاج.
- موافقة بشرية قبل أي تعديل كود إنتاج بسبب فشل اختبار (يُحوّل لمسار الإصلاح).

## المخرجات النهائية
- اختبارات جديدة تغطّي المسارات الحرجة الناقصة.
- نتائج تشغيل وتحليل إخفاقات.
- تقرير نهائي (report-template) + ذاكرة محدّثة بحالة التغطية.
