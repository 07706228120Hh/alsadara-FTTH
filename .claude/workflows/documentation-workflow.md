# Documentation Workflow — سير عمل التوثيق

الهدف: توثيق دقيق يعتمد على الكود الفعلي فقط دون افتراضات.

## السلسلة
```
Documentation Task
  → documentation-agent
  → Inspect Real Code (فحص الكود الفعلي)
  → Update Docs (تحديث التوثيق)
  → Avoid Assumptions (تجنّب الافتراضات)
  → knowledge-manager-agent (Memory Update)
  → Final Summary
```

## الخطوات بالتفصيل
1. **documentation-agent**: يستلم مهمة التوثيق ويحدد النطاق (Backend / Flutter / API / DB). المخرجات: task-template.
2. **Inspect Real Code**: قراءة الكود والمسارات الفعلية (src/Backend/**، src/Apps/**) قبل كتابة أي شيء. المخرجات: مراجع ملفات وسطور.
3. **Update Docs**: تحديث التوثيق ليطابق السلوك الفعلي للنظام (Endpoints، نماذج البيانات، التدفقات). المخرجات: توثيق محدّث.
4. **Avoid Assumptions**: ممنوع توثيق سلوك غير مؤكد من الكود؛ أي غموض يُعلَّم بوضوح ويُسأل عنه بدل افتراضه. المخرجات: ملاحظات نقاط الغموض.
5. **code-reviewer-agent** (إن لزم): مراجعة مطابقة التوثيق للكود.
6. **security-auditor-agent** (إن لزم): التأكد أن التوثيق لا يكشف أي أسرار أو IPs/مفاتيح حساسة بشكل غير لائق.
7. **knowledge-manager-agent**: تحديث الذاكرة (`MEMORY.md` والملفات المرتبطة) إذا تغيّرت مراجع رئيسية.

## بوابات الموافقة البشرية
- موافقة بشرية قبل نشر أي توثيق عام يحتوي تفاصيل بنية تحتية حساسة.
- ممنوع كشف secrets أو بيانات اعتماد في التوثيق إطلاقاً.

## المخرجات النهائية
- توثيق دقيق مطابق للكود الفعلي.
- قائمة نقاط الغموض التي تحتاج توضيحاً بشرياً.
- ملخّص نهائي (report-template) + ذاكرة محدّثة عند اللزوم.
